3. Habilitar API en la instancia autohospedada y, si procede, una allowlist de IP según política del dueño. Emitir un token de equipo limitado **sólo al recurso demo**, con permisos `read` + `deploy`, vencimiento corto y sin `write`, `delete`, `read:sensitive` ni `root`. Guardarlo sólo como `COOLIFY_TOKEN` del GitHub Environment `coolify-demo`, con aprobación del dueño y política de rama protegida `develop`. No imprimir ni subir el token.

[Coolify documenta](https://coolify.io/docs/api/permissions) que `read` permite estado y `deploy` permite disparar despliegues, pero también reinicios, paradas y cancelaciones; el alcance de recurso y la separación de servidor limitan el impacto. Un token con `write` para Compose puede alcanzar el host mediante mounts, incluso con alcance de proyecto reducido. [La API autohospedada](https://coolify.io/docs/api/overview) requiere habilitación explícita y admite restricción por IP.
