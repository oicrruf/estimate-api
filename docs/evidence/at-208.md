# AT-208: evidencia local y límites

Fecha: 2026-11-26. Base: `develop` `c503575e152430908da3f0bb56317867e77d26c9`.
Se usaron únicamente identidades, proyectos y ofertas sintéticos. No se conectó al proyecto Supabase alojado.

## Ejecución reproducible

Desde la raíz del repositorio, con Docker disponible:

```bash
bash tests/at208/run_local.sh
```

El script crea un contenedor `postgres:17-alpine` sin red ni puerto publicado y lo elimina al terminar. Aplica un fixture local de roles y `auth.uid()` simulado, la migración versionada, y pruebas SQL. Exporta la base con `pg_dump -Fc`, restaura otra base con `pg_restore`, comprueba que el usuario B solo ve su proyecto, y restaura después la copia del esquema anterior a la migración. La salida observada fue:

```text
AT-208 domain and RLS assertions passed
AT-208 local migration, RLS, backup/restore and baseline rollback passed
```

El test comprueba dos proyectos, cuatro usuarios (propietarios, editor y viewer), rechazo de relaciones/ofertas entre proyectos, un máximo de un presupuesto activo, fechas inválidas, snapshots y ofertas sin edición directa, auditoría, transferencia de propiedad y fallo cerrado sin identidad. La restauración prueba legibilidad y un caso de aislamiento; no mide RPO/RTO ni sustituye un simulacro con datos reales.

OpenSpec CLI `@fission-ai/openspec` 2.2.0: `openspec validate at-208-postgres-domain --strict` → `Change 'at-208-postgres-domain' is valid`.
`uv run --no-sync python scripts/check_secrets.py` → `No potential secrets detected`.
`uv run --no-sync pytest -q` → `61 passed, 1 warning` (deprecación de Starlette/AnyIO).

La migración fue creada con `supabase@3.4.0 migration new at_208_postgres_domain` dentro de un contenedor Node debido a que el CLI local intentó escribir en un home de solo lectura. El fixture `tests/at208/local_auth_fixture.sql` no debe desplegarse: acepta un claim simulado y no valida JWT. La migración requiere los roles y objetos `auth` provistos por Supabase. No se verificaron políticas en el proyecto alojado, ni auth JWT, ni backup administrado de Supabase, ni despliegue.

## Revisión requerida

Antes de integrar, un revisor independiente debe inspeccionar especialmente `SECURITY DEFINER`, el `search_path`, la excepción `audit_events` sin FORCE RLS, grants de columnas, transición de propietario, y si la configuración real de Supabase expone únicamente el esquema esperado. El CI ejecuta el mismo script local. La revisión no se ha hecho en este trabajo.
